## 教學：這一輪學到的五件事

### 1. MedSAM 怎麼變成 6 個點

MedSAM 只會輸出遮罩，不會輸出點，所以中間要接一段幾何。

1. **裁切**：以框的中心為準，從原圖裁出 2.2 倍椎體大小的正方形，縮放成 512²。
2. **分割**：encoder 把裁切後的影像轉成特徵，decoder 依提示框輸出 128² 的遮罩。
3. **找輪廓**：遮罩放大回 512²，取最大的連通區塊，描出外輪廓。
4. **決定方向**：判斷前方和下方各在哪裡。
   - 修正既有的一節時，用那節原本的點位決定。
   - 新增一節時，用遮罩的最小外接矩形決定，再拿鄰近椎體的方向挑出「下方」，傾斜超過 45° 時才判得對。
5. **取點**：四個角點是輪廓上沿對角線方向最遠的點。中點是上下終板弧線上、位在弦長一半處的點。
6. **轉回原圖**：用反仿射轉換換回原圖座標。

**訓練方式**：把醫師的 6 點連成六邊形當作標準答案遮罩。encoder 凍結，只訓練 mask decoder（4M 參數），4060 上 512 版 5 折共 31 分鐘。

### 2. 為什麼 512 不會比 1024 差

- **原圖本來就沒那麼大**：一節椎體在原圖約 300 px，裁切範圍約 660 px。1024 等於把原圖放大 1.5 倍，多出來的像素沒有新資訊。512 已經接近原圖解析度，encoder 的運算量卻少約 4 倍，注意力的運算更少。
- **怎麼改成 512**：SAM 的位置編碼原本是 64×64，要內插成 32×32。全域注意力的相對位置編碼也要內插，transformers 會自動處理。見 `medsam_refine.resized_sam()`。

### 3. 為什麼 int8 在顯示卡上反而最慢

- **int8 量化只對 CPU 有利**：它把矩陣乘法改成 `MatMulInteger` 這類運算，WebGPU 不支援，只好退回 CPU 執行，資料還要在 GPU 和 CPU 之間來回搬。
- **顯示卡要用 fp16**：運算一樣在 GPU 上，檔案只有一半，和 PyTorch 的遮罩 IoU 是 0.9999。
- **對應原則**：WebGPU 用 fp16，只有 CPU 時才考慮 int8。

### 4. 為什麼醫院只能單執行緒

- **限制來源**：雙擊打開本機 HTML（file://）時，瀏覽器不允許 SharedArrayBuffer，WASM 只能單執行緒。
- **影響有多大**：家裡實測單執行緒 16 秒，8 執行緒 3.9 秒。
- **怎麼解**：要多執行緒，網頁必須用 https 並帶 COOP/COEP 標頭，例如放到 GitHub Pages。醫院有 WebGPU 可用，所以這次不需要。

### 5. 外部測試集的三道防護

外部測試集是 `holdout_20261029`，46 張。這些影像的標準答案不能被模型拉向模型自己的輸出，所以兩種模式都要擋。

| 模式 | 防護 |
|---|---|
| 本機服務 | 上傳檔案的 SHA-256、前端宣稱的 SHA-256、解碼後灰階像素的雜湊，三種任一符合就拒絕 |
| 瀏覽器 | 原始檔的 SHA-256，或 R 通道像素指紋，任一符合就拒絕 |

- **瀏覽器的清單從哪來**：雜湊清單是 `holdout_hashes.json`，由 `export_medsam_onnx.py` 從 manifest 產生，只有雜湊、沒有影像和病歷號。
- **少了清單會怎樣**：缺少這個檔，瀏覽器模式不會啟用。
- **防的是哪種情況**：像素指紋是為了貼上或重新存檔的影像。這時檔案位元組變了，但像素沒變。

## 已知限制與待辦

- **S1、T12 沒有驗證**：這類只有一個終板的椎體，拉框結果沒經過 OOF 驗證，因為模型只用完整椎體訓練。用的時候要逐節看。
- **點位移動可能翻轉骨折標記**：同一張影像，1024 版修整後 L3 被標成前緣壓迫，512 版變成 L2。MedSAM 讓點位移動幾 px，高度比就可能越過門檻。骨折判讀一定要醫師看過原圖。
- **外部測試集還沒重標**：21 張外部測試集（16 張腰椎、5 張頸椎）仍是 AI 預標，要手動重標。MedSAM 在這些影像上會被拒絕，這是刻意的。
- **醫院要能連 CDN**：onnxruntime-web 從 cdn.jsdelivr.net 載入。如果醫院擋外網，要改成把 `ort.webgpu.min.js` 和 wasm 檔放在本機，目前還沒做。
- **公開 repo 裡有舊病歷號**：`HANDOFF_2026-06-06.md` 等舊交班檔有真實病歷號，要清除必須改寫 git 歷史。新檔一律用假編號。
- **Colab**：可以拿來訓練，但不適合當服務，官方 FAQ 禁止架設和互動運算無關的網路服務。目前擱置。

commit 前請另一個沒看過程式的 agent 審查瀏覽器模式與匯出腳本。它確認 JS 移植和 Python 等價、沒有競態問題，另外找出 9 個問題，全部已修。

| # | 問題 | 修正 |
|---|---|---|
| 1 | **外部測試集清單是空的也會啟用瀏覽器模式**（最嚴重） | 匯出時清單不完整就停止；瀏覽器載入時清單筆數必須大於 0 |

## 醫院測試步驟

### 要帶的檔案

從 `endplate_training_data/onnx/medsam_20261124_s512/` 帶以下 4 個檔，再加上 `spinal-annotation-web.html`，共 5 個檔。放在同一個資料夾，例如隨身碟的 `medsam/`。

| 檔案 | 大小 | 用途 |
|---|---:|---|
| `encoder_fp16.onnx` | 177 MB | 影像特徵（WebGPU 用） |
| `decoder.onnx` | 19 MB | 依框輸出遮罩 |
| `meta.json` | 小 | 前處理設定、檔案雜湊 |
| `holdout_hashes.json` | 小 | 外部測試集阻擋清單（只有雜湊） |
| `spinal-annotation-web.html` | | 標註工具 |

**注意**：

- 不要帶 `encoder.onnx`（fp32，比 fp16 大一倍，速度沒有比較快）。
- 上次測速用的 `encoder512_fp16.onnx` 不能用。瀏覽器只認 `encoder_fp16.onnx` 這個檔名，雜湊也要和 meta.json 一致，所以這次要用重新匯出的檔。
- 前一次帶去的模型資料夾要整個換掉，不要混用。

### 步驟

1. **打開工具**：用 Chrome 直接雙擊 `spinal-annotation-web.html`。
2. **載入影像與標註**：照平常方式選一張**不在外部測試集**的影像和它的 JSON。
3. **載入模型**：按「📦 瀏覽器模型」，在選檔視窗裡按 Ctrl+A 選取上面 4 個模型檔，按開啟。
4. **確認狀態列**：要看到「WebGPU，encoder_fp16.onnx，512²；外部測試集 46 張（清單 2026-11-24）」。
   - 顯示「CPU（較慢）」，代表 WebGPU 沒建起來，每節會要 30 秒左右。請記下來回報。
   - 跳出「缺少 holdout_hashes.json」「不是同一次匯出」「與 meta.json 記錄的不同」這類訊息，代表檔案沒帶齊或混到舊檔。
5. **修整全部**：按「🧠 修整全部」，用手機碼表計時。家裡 5 節約 2.3 秒；醫院預期每節 1.3 秒，5 節約 6 到 7 秒，第一次會多幾秒做初始化。
6. **框選一節**：按「🧠 MedSAM 框選」，在一節椎體上拉框，看 6 點是否合理。
7. **外部測試集要被拒絕**：開一張外部測試集影像，按「🧠 MedSAM 框選」。要跳出「這張是外部測試集…不提供 MedSAM 輔助」。
8. **下次開啟不用重選**：關掉 Chrome 再打開工具，直接按「🧠 MedSAM 框選」。應該不用再選檔就能用（模型存在瀏覽器裡 30 天）。
